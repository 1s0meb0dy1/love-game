# ASK ME — игра для пар и компаний

Проект собирается через Vite. Весь код приложения лежит в `src/app.jsx`, стили — в `src/styles.css`.

## Команды
| Команда | Что делает |
|---|---|
| `npm install` | устанавливает зависимости (один раз) |
| `npm run dev` | локальный сервер для разработки |
| `npm test` | все автотесты: логика (`tests/unit`) и интерфейс (`tests/ui`) |
| `npm run test:unit` / `npm run test:ui` | только логика / только интерфейс |
| `npm run build` | боевая сборка в `dist/` (минификация, service worker, Brotli и gzip) |
| `npm run size` | проверка веса сборки (лимиты ниже) |
| `npm run verify` | тесты → сборка → проверка веса (то же, что в CI) |

## Проверка перед каждой загрузкой на GitHub
1. Один раз: `git config core.hooksPath .githooks` — перед каждым `git push` автоматически запускается `npm run verify`; если что-то не прошло, отправка отменяется.
2. В GitHub: Settings → Pages → Source: **GitHub Actions**. После этого каждый push в `main` запускает `.github/workflows/ci.yml`: тесты → сборка → проверка веса → публикация. Если тесты упали, сайт не обновится.

## Игра на нескольких устройствах
Синхронизация включена по умолчанию в обычном и усложнённом режимах — отдельного режима нет. Все устройства одной сессии видят один вопрос и одного отвечающего; «Далее» можно нажимать на любом. **Устройств в игре не больше, чем игроков в сессии** (и не больше 10): лишнее устройство не пускают и объясняют, как увеличить лимит (добавить игроков в «Игроки и сессия»). Число считается по свежим отметкам устройств в комнате (`deviceCap` в `src/app.jsx`), проверяется при подключении (`joinLive`) и при возвращении в начатую игру; считается по большему из своих игроков и игроков в комнате (`snap.pl`), чтобы устаревшая копия сессии не давала ложных отказов. Лимит клиентский: правила базы его не держат (два устройства, входящие одновременно, могут превысить его на одно). Только тестовый режим владельца работает сам по себе и ничего не пишет в базу. Вся база вопросов (а не только первые 400) участвует в партии.
- **Один игрок — без синхронизации.** Пока играет одно устройство, в комнату уходит лишь «маячок»: `solo`, число вопросов, «отпечаток» колоды (`dk`) и режим. Имён игроков, списка вопросов и хода игры в нём нет. Хозяин раз в 2 секунды смотрит, не появился ли второй.
- **Синхронизация начинается со второго устройства.** Подключаясь, устройство отмечается в комнате; хозяин, увидев его, записывает колоду целиком отдельным узлом `live/<комната>_d` и включает игроков/ход в комнате (`pl`, `idx`, `max`, `hist`). Если хозяин не отвечает 15 секунд, подключающемуся показывают понятное сообщение и его отметка убирается.
- Комната — `/live/l_<хеш ключа сессии>`: узнать её имя можно, только зная ключ сессии. Тексты вопросов в комнату не попадают. Данные комнаты **не шифруются** (шифруется только облачная копия самой сессии) — это указано в политике конфиденциальности.
- Приложение раз в секунду проверяет номер версии комнаты (только пока идёт синхронизация) и забирает снимок при изменении, раз в 8 секунд отмечается «я здесь». Отметка старше 30 секунд — устройство не считается в игре.
- Выход одного устройства не завершает партию; «Для всех» завершает её у всех и удаляет колоду. Если хозяин хода пропал, наказание за таймер выдаёт одно из оставшихся устройств (по очереди).
- Правила Firebase для узла `live` заданы в консоли Firebase (файл правил в репозиторий не кладём, чтобы не публиковать идентификатор владельца); их копия без идентификатора владельца — `firebase/database.rules.template.json` (по ней работают и эмулятор в CI, и база в памяти для UI-тестов, которая отклоняет поля комнаты, не разрешённые правилами); для узла `sessions` есть ещё `tests/fixtures/sessions-rules.json` — если меняете правила, обновите шаблон и эту копию. Локальный файл `database.rules.json` (если он у вас есть) внесён в `.gitignore`.
- Проверки: `tests/ui/live*.test.js` (несколько окон на общей базе в памяти с теми же ограничениями) и `tests/unit/live-logic.test.js`. Настоящий Firebase автотесты не трогают.

## Режим «Правда или действие»
Отдельный режим (карточка на экране режимов, `#/tod` → `#/tod/play` → `#/tod/results`). Игрок выбирает «Правду» или «Действие» (у действия три уровня), задание выполняют или пропускают; пропуск не передаёт ход. **«Правда» — не больше трёх раз подряд** (`TOD_TRUTH_LIMIT`, `todTruthLocked` в `src/tod/engine.js`): после третьей кнопка запирается, а `todApply` отклоняет четвёртую с причиной `locked`; серию сбрасывает выбор «Действия», у каждого игрока она своя. Правило описано в лобби, а на экране хода видны три точки серии и объяснение. В конце — «Зал позора» и добрые титулы. Жёсткие карточки и острый тон подколок — только 18+, по умолчанию выключены.
- **Файлы.** `src/content/tod-cards.js` — стартовый набор карточек; `src/content/tod-banter.js` — события, реплики-подколки и титулы; `src/tod/model.js` — проверка и чистка карточки; `src/tod/cards.js` — загрузка из базы, кэш устройства (`askme_tod_cards_v1`), запись из админки; `src/tod/deck.js` — колода без повторов (пулы `truth`, `dare.easy|medium|hard`, до 120 карточек в каждом, перемешивание по seed); `src/tod/engine.js` — движок партии (`todApply`, `todSanitize`); `src/tod/talk.js` и `src/tod/titles.js` — выбор реплики и титулы; `src/tod/channel.js` — синхронизация; `src/tod/screens.jsx` — экраны (архив, админка `#/tod/manage`, лобби, игра, итоги). **Свои карточки** игроков (`src/tod/mine.js`, ключ `askme_tod_mine_v1`, до 30 штук, id `my_…`) лежат только на устройстве и в базу не уходят: в лобби их включает переключатель «Добавить мои карточки»; на других устройствах сессии вместо текста показывается подсказка «её прочитает автор». В архиве «Все вопросы» владелец правит и скрывает карточки кнопками «Изменить» / «Скрыть» (форма открывается сразу на нужной карточке). В `src/tod/*` все верхнеуровневые имена начинаются с `tod`/`Tod`/`TOD_`, импорты однострочные: тестовый харнесс подставляет модули в общий код `app.jsx`.
- **Карточки в базе:** `tod/<id>` = `{ id, type: 'truth'|'dare', difficulty: 'easy'|'medium'|'hard', text (1–300 знаков), isActive, updatedAt? }`, `id` — `td_` + base36, не длиннее 16 знаков. Читать может любой, писать — только владелец. Правило есть в шаблоне `firebase/database.rules.template.json` (копия узла для unit-тестов — `tests/fixtures/tod-rules.json`). Канал партии требует в правилах `live/$room` поле `st` (строка до 20000): без него база отклонит ход, потому что у комнаты стоит `$other: false`. **Порядок публикации:** сначала правило `tod` в консоли Firebase, потом приложение; затем владелец в админке нажимает «Загрузить стартовый набор».
- **Канал партии:** `live/<комната>_t` = `{ ver, by, t, status: 'active'|'ended', ids, st, p }`, где `ids` — колода строкой JSON (не длиннее 12000), `st` — состояние партии строкой JSON (клиент держит не длиннее 20000), `p` — отметки устройств. Партия пишется сразу при старте, даже на одном устройстве. Остальные устройства видят приглашение («Идёт игра «Правда или действие»») и входят; ход меняется ровно один раз при одновременных нажатиях (при равном `seq` побеждает запись в базе). Раз в секунду проверяется `ver`, раз в 8 секунд — «я здесь». После перезагрузки на `#/tod/play` или `#/tod/results` партия читается из канала; если её нет или она испорчена — главная. Пока в комнате сессии идёт классическая живая игра, новую партию не начать. Адреса `#/tod…` защищены от автообновления (`inGameHash` в `src/update.js`).
- **Известные ограничения:** старые узлы `_t` не чистятся (перезаписываются новой партией этой сессии, стираются кнопкой «Удалить мои данные»); классическая игра и «Правда или действие» одновременно в одной сессии не идут; лимит устройств, как и в классической игре, клиентский.
- **Как добавить реплику:** объект `{ id: '<событие>_<n>', ev, tone: 1|2, text, tags? }` в `TOD_BANTER` (`tone: 2` — острый, 18+; `tags: ['ua']` — политическая сатира), подстановки `{name}` и `{форма для него|для неё}`; украинский перевод — в словарь `UK` в `src/i18n.js` с тем же ключом. **Карточку** владелец добавляет в админке; в стартовый набор — объектом в `src/content/tod-cards.js`. Проверки — `tests/unit/content.test.js`.
- **Для магазинов приложений:** возрастная метка 17+/18+; анкеты Apple и IARC (Google Play) заполнять честно: грубая лексика, откровенные темы, политическая сатира. Учитывать правило Apple 1.1 (оскорбительный контент) и политики Google Play о чувствительных событиях и разжигании ненависти: сатира направлена на государство-агрессора, а не на народ или группу людей.
- Проверки: `tests/unit/tod-*.test.js`, `tests/ui/tod-*.test.js` (`tod-live` — несколько устройств, `tod-resume` — перезагрузка).

## Прошлые игры сессии
Меню → «Прошлые игры» (`#/history`): список завершённых партий по дням и страница итогов конкретной игры (`#/history/view`, как экран «Игра завершена»: кольцо, уровни, кто как играл, главные темы). Запись создаёт `handleFinishGame` (обычный и усложнённый режимы; тестовый режим и пустые партии не пишутся) через `histBuild` из `src/history/model.js`; хранится в `profile.history` (новые первыми, не больше 20 — `HIST_MAX`) и уходит в зашифрованную облачную копию вместе с профилем (`history` в `src/session-io.js`; при слиянии двух копий записи объединяются по id — `histMerge`). Удаления записей нет: список сам обрезается до 20. У **самой последней** игры, которая остановилась на середине колоды, в записи лежит снимок партии (`res`, чистится как `savedGame`): кнопка «Продолжить игру» кладёт его в `profile.savedGame` и открывает партию, запись помечается «продолжена» (`cont`) и снимок теряет; если уже есть начатая игра, приложение спрашивает подтверждение. Для игры, дошедшей до последнего вопроса, и для «вся колода» снимка нет — вместо «Продолжить» кнопка «Сыграть ещё». Экраны: `src/history/screens.jsx`; проверки: `tests/unit/history.test.js`, `tests/ui/history.test.js`.

## Приглашение игроков (ссылка и QR)
- Кнопка «Пригласить игроков» (иконка «поделиться» в шапке экранов «Выберите режим» `#/mode` и «Усложнённый режим» `#/setup`, большая кнопка в меню `#/more`) → страница `#/invite`; «Назад» возвращает на тот экран, откуда пришли (`inviteFrom`). На странице: QR-код (рисуется прямо в разметке библиотекой `qrcode-generator`, внешних сервисов нет), кнопки «Поделиться ссылкой» / «Скопировать ссылку».
- Ссылка имеет вид `…/#/join?sid=<ID сессии>&key=<ключ шифрования>`. **Ключ даёт полный доступ к сессии**, поэтому на экране он замаскирован, а при открытии ссылки сразу вырезается из адресной строки. Старые ссылки `#/welcome?sid=…&key=…` продолжают работать.
- Страница `#/join` открывается без сессии и показывает один из экранов: «Вас пригласили» (новое устройство), «Вы уже в этой сессии», «Перейти в другую сессию?» (прежняя остаётся в облаке), «Ссылка не подошла». После «Присоединиться» сессия берётся из облака, а если в ней идёт игра, устройство само входит в неё (в течение 20 секунд).
- **Вход по ID.** Ключ сессии (128 бит) есть на устройствах и в ссылке, а ID — всего 40 бит, поэтому по одному ID облачную копию найти нельзя. Чтобы на новом устройстве можно было войти по ID, устройство кладёт в облако «замок» `sessions/j_<…>`: ключ сессии, зашифрованный AES-GCM ключом, выведенным из ID функцией PBKDF2 (300 000 кругов, SHA-256, соль `askme-join-v1`). Из того же вывода PBKDF2 берётся и адрес замка, поэтому ID по содержимому облака не узнать, а подбор требует полного расчёта на каждую попытку. Это защита уровня «код комнаты» (знающий ID может войти) — она описана в политике конфиденциальности. Замок пишется отдельным узлом `sessions` (новых правил Firebase не нужно: `payload` строка короче предела + `updatedAt`), при первом запуске сессии на устройстве, затем раз в неделю (`profile.joinAt`); старые сессии получают замок при первом запуске после обновления. Сессии старого формата (`sess_<хеш ID>`, до ключей) по-прежнему входят по ID. Код: `joinCodeParts`, `publishJoinCode`, `lookupJoinCode`, `removeJoinCode` в `src/app.jsx`; проверка — `tests/ui/id-login.test.js` (схема пересчитывается независимо от приложения). **ID открывает сессию, поэтому он нигде не должен лежать открытым:** в статистику (`analytics/full`) он не отправляется (раньше отправлялся; правило базы требует поле `sid`, поэтому приложение шлёт в нём пустую строку, и она затирает старый ID при следующей записи; записи тех, кто больше не играл, можно очистить в консоли Firebase), ID создаётся через `crypto.getRandomValues`. Правила `analytics/*` лежат в консоли Firebase; их копия для тестов — `tests/fixtures/analytics-rules.json` (чтение только у владельца, запись `analytics/full` требует `updatedAt`, `sid`, `names`). У узлов `sessions` и `live` чтения списком нет: перечислить чужие сессии и комнаты нельзя, только открыть известный адрес. Известные ограничения: 40-битный ID — защита уровня «код комнаты»; «замок» живёт, пока его обновляет хоть одно устройство; запись замка не повторяется при сбое сети до перезапуска приложения.
- «Удалить мои данные» (меню → «Игроки и сессия») стирает облачную копию сессии, общую комнату с колодой, записи статистики этого устройства и локальное хранилище. Если облако не ответило — ничего не стирается, пользователь видит причину.
- Облачная копия сессии ограничена правилом базы (`payload` короче 60000 знаков; число `SESSION_PAYLOAD_MAX` в `src/app.jsx` на 1000 меньше). Если незавершённая партия со всей колодой не помещается, в облако уходит сессия без неё (партия остаётся на устройстве); если не помещается и это — показывается сообщение. Меняете правило в консоли Firebase — меняйте и `SESSION_PAYLOAD_MAX`, и копию `tests/fixtures/sessions-rules.json`; сначала публикуйте правило, потом приложение.

## Страницы «Об игре» и юридические документы
Весь текст лежит в двух файлах — код менять не нужно:
- `src/content/about.js` — страница «Об игре» (`#/about`): заголовок, шаги, возможности (с группами-фильтрами), «Чем отличается», FAQ, призыв, блок «Попробуйте» (`demo.examples` — ровно по 3 вопроса на каждую глубину, без темы «Интим»; кнопка листает их по кругу). Числа подставляются сами из базы: `{questions}`, `{topics}`, `{players}`, `{devices}`, а `{questions#вопрос,вопроса,вопросов}` ещё и склоняет слово. Новая возможность — это один объект в `features`. Дату `updated` меняйте, когда правите страницу. Страницей можно поделиться (кнопка в шапке — копирует `…/#/about`, без сессии она открывается как обычная страница сайта).
- `src/content/legal.js` — политика конфиденциальности, пользовательское соглашение, cookies и локальное хранилище, возраст 18+ (`#/privacy`, `#/terms`, `#/cookies`, `#/age`). Заполните `operator` (как вас называть) и `contact` (куда писать; сейчас — публичные обращения проекта на GitHub, почта нигде не показывается). Разделы со звёздочкой в заголовке (` *`) описывают поведение игры, которое вы можете изменить, — после изменений поправьте текст. **Это шаблон по тому, что игра реально делает с данными, а не юридическая консультация**: перед рекламой, монетизацией или запуском в другой стране покажите его юристу.
- Ссылки на документы стоят в самом низу меню и в подвале, мелким приглушённым текстом.
- `tests/unit/content.test.js` ловит пустые поля, повторы id, неизвестные заготовки, случайно вписанную почту и забытые ключи хранилища в таблице cookies; `tests/ui/about-legal.test.js` проверяет сами страницы.

## Лимиты веса (меняются переменными окружения)
- весь сайт: `MAX_TOTAL_MB` = 15 МБ
- первая загрузка (HTML+CSS+JS в gzip): `MAX_INITIAL_GZIP_KB` = 500 КБ
- один рисунок: `MAX_IMAGE_KB` = 150 КБ, один звук или видео: `MAX_MEDIA_KB` = 100 КБ

Звуки в приложении синтезируются в браузере (Web Audio), отдельных аудиофайлов нет. Если когда-нибудь добавите файлы, кладите их в `public/` в формате Opus или MP3: проверка веса не даст выложить слишком тяжёлый файл. Иконки перегенерируются командой `python scripts/make-icons.py`.

## Офлайн и обновления
Service worker (генерирует `vite-plugin-pwa`, режим `prompt`) кэширует приложение и шрифты, поэтому игра открывается без сети и быстро. Новая версия скачивается в фоне, но страница перезагружается на неё **только вне партии** (`src/main.jsx`, `src/update.js`: пока адрес — игра, разбор ответа, итоги, приглашение, создание сессии, профиль, добавление/правка вопроса или вход владельца (список в `src/update.js`), перезагрузка откладывается и проверяется раз в 3 секунды). Раньше автообновление могло перезагрузить страницу посреди игры. Ограничение: если новую версию применит другая вкладка этого же сайта (или установленное приложение), все открытые вкладки перезагрузятся сами — это делает `vite-plugin-pwa`; игра при этом возвращается из сохранения (см. ниже).

## Возврат в начатую игру
Если страница на экране игры перезагрузилась (обновление, фоновая вкладка на телефоне), партия берётся из сохранения на устройстве (`profile.savedGame`) и открывается на том же вопросе; если сохранения нет или оно битое — открывается главная (адрес `#/play` при этом заменяется, «Назад» на него не возвращает). Возврат ждёт, пока посчитается имя общей комнаты, чтобы устройство вошло в идущую игру, а не играло в одиночку. **Чужую идущую игру возврат не затирает:** если в комнате играют другие устройства, а подключиться к ним не вышло (другая колода, нет места, хозяин не ответил), устройство открывает главную с приглашением «Присоединиться» (ручное «Продолжить игру» объясняет причину сообщением). Для `#/summary` и `#/ai` после перезагрузки показывается главная с кнопкой «Продолжить игру». Проверки: `tests/ui/game-resume.test.js`, `tests/ui/resume-guard.test.js`, `tests/unit/update.test.js`.

## Таймер на ответ
В усложнённом режиме время на ответ выбирается от 30 секунд до 7 минут (шаг 5 с, быстрые значения 30 / 45 / 60 / 90 / 120 с; константы `TIMER_MIN`, `TIMER_MAX` в `src/app.jsx`). Значения короче 30 с, сохранённые прежними версиями, при чтении настроек не меняются (нижняя граница чтения — 5 с).
