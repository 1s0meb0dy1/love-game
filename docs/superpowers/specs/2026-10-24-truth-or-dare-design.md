# Режим «Правда или действие» — проект (спека)

Дата: 24.10.2026. Статус: **утверждена владельцем 24.10.2026**, код ещё не писался.
Путь: архитектурная задача → эта спека → план реализации (`docs/superpowers/plans/2026-10-24-truth-or-dare.md`) → этапы.

## 1. Цель и критерии успеха

Новый игровой режим для компаний и пар внутри ASK ME: игроки по кругу выбирают «Правду» или «Действие» (у действия — три уровня), получают карточку, выполняют её или пропускают. Пропуск позорный: над ним шутят прямо в игре, а в итогах есть «Зал позора». Все устройства сессии видят одно и то же в реальном времени.

Успех:
- режим запускается с экрана «Выберите режим» и играется на 2–10 устройствах одной сессии без рассинхрона (чей ход, что выбрано, какой текст);
- в рамках одной игры карточки не повторяются;
- владелец управляет базой карточек из админки (добавить, изменить, скрыть/показать) без обновления приложения;
- «Все вопросы» показывают карточки отдельными вкладками;
- классическая игра не затронута, `npm run verify` проходит.

## 2. Решения владельца

| Тема | Решение |
|---|---|
| Комнаты | Внутри текущей сессии. Кодов комнат и ввода имён нет: игроки берутся из сессии, остальные устройства подключаются как сейчас (ссылка, ID, «Поделиться сессией»). Устройств не больше, чем игроков, максимум 10 |
| Уровни | `easy` / `medium` / `hard`. «Жёсткие» — откровенные, 18+ |
| Наказаний нет | Заменены пропуском с позором |
| Пропуск | Кнопка «Пропустить» есть всегда, в том числе на повторной карточке. Пропустивший **сам тянет следующую** и остаётся «у доски», пока не ответит или не выполнит. Следующий игрок ходит только после этого |
| Каждый пропуск | Встречается подколкой; чем больше пропусков подряд, тем острее |
| Тон | «Выкл / Мягкий / Острый». Острый: немного вульгарности, чёрный юмор, политическая сатира на государство-агрессора |
| Титулы | Расширенный список позорных и добрых (раздел 9) |
| Предупреждение 18+ | Обязательно (раздел 10) |
| Подход | Отдельный канал синхронизации `live/l_<хеш>_t`, не встроенный в классическую комнату |

## 3. Что принято в ходе проектирования (проверьте)

- Любое устройство сессии может нажимать кнопки хода («Выбрать», «Выполнено», «Пропустить»), как «Далее» в классической игре: устройств может быть меньше, чем игроков, и телефон иногда передают по кругу. Защита от случайного двойного нажатия: защитный интервал 500 мс и номер действия `seq` (раздел 6).
- Особых прав «ведущего» нет. «Ведущий» — устройство, нажавшее «Начать игру»: оно задаёт опции (Жёсткие, тон) и записывает колоду. После старта все устройства равны, ушёл ведущий — игра продолжается.
- Для старта нужно минимум 2 игрока в сессии и хотя бы одна активная карточка нужных типов.
- Игра идёт, пока кто-то не нажмёт «Завершить» (с подтверждением). Закончилась колода — перемешиваем и продолжаем.
- «Правда» берётся случайно из разрешённых уровней: подменю уровней только у «Действия».
- Аналитику для режима не пишем (YAGNI). Локализацию не начинаем: все тексты на русском, как весь контент проекта.

Из-за общей области видимости верхнеуровневые имена в `src/tod/` уникальны (префикс `tod`/`Tod`); из `React` берём только `React.useState` и т. п., без деструктуризации в модуле.

- Тестовая база `tests/fake-rtdb.js` сейчас применяет только правила `live`. Её расширяем правилами из `tests/fixtures/tod-rules.json`, чтобы тесты проверяли запись карточек так же, как проверит Firebase.

## 6. Данные Firebase

### 6.1 Узел `tod/<id>`

```
tod/<id> = { id, type, difficulty, text, isActive, updatedAt? }
  id          строка, равна ключу; формат 'td_' + base36
  type        'truth' | 'dare'
  difficulty  'easy' | 'medium' | 'hard'
  text        строка, 1–300 знаков
  isActive    логическое: false — карточка скрыта из игры, но остаётся в базе
  updatedAt   число, ставится админкой
```

Правила (черновик, копия лежит в `tests/fixtures/tod-rules.json`, идентификатор владельца заменён на `OWNER_UID`):
- `.read: true` (как у `questions`, без входа); `.write` — только владелец по `uid`;
- `.validate` карточки: все пять полей, `id === $id` и длина `id` не больше 16 знаков, значения из списка, `text` 1–300, `isActive` — boolean, лишние поля запрещены;
- удалять запись можно только владельцу, но в админке кнопки удаления нет (soft delete).

**Публикация правил в боевую базу — только после явного «да» владельца** (для этого нужен вход в Firebase; предыдущий вход закрыт). Правила `live`, `sessions`, `analytics` не меняются.

### 6.2 Загрузка и запасной набор

- Приложение читает `tod.json` один раз за сессию приложения, кладёт копию в `localStorage` (как шаблоны наказаний), без сети берёт копию.
- Если база пуста или недоступна и копии нет, используется встроенный стартовый набор (`tod-cards.js`, около 20 карточек на каждую из шести групп «тип × уровень»).
- Админка содержит разовую кнопку «Загрузить стартовый набор в базу» (по одной карточке, пропуская существующие `id`).
- Для игры берутся только `isActive === true`; владелец в админке видит все.

### 6.3 Канал игры `live/l_<хеш>_t`

Имя комнаты — то же, что у классической игры (`liveRoomKey(sessionKey)`), с суффиксом `_t` (по образцу `_d`). Правило `live/$room` его уже пропускает: требуются `ver`, `by`, `t`.

```
ver, by, t        версия записи (как в классической игре: у каждого устройства своя дробная часть)
status            'active' | 'ended'
p                 присутствие устройств: { <deviceId>: <время> }, живо 30 с, отметка раз в 8 с
ids               колода: JSON-строка (<= 12000 знаков, правило узла live), см. раздел 7
st                состояние игры: JSON-строка (<= 20000 знаков, проверяется приложением)
```

Приватность: узел не шифруется (как остальные комнаты `live`), в нём имена игроков, выборы и статистика пропусков. Это нужно описать в политике конфиденциальности (раздел 10).

Лимиты в правилах: сейчас `live/$room` ограничивает только `ids` (до 12000 знаков). Размер `st` (до 20000) и `p` проверяет только клиент, как и для классической комнаты. Необязательное усиление: добавить в `live/$room` проверку `st` не длиннее 20000 знаков (классическая игра поля `st` не использует). Делаем только по отдельному «да» вместе с публикацией правил `tod`.

## 7. Колода без повторов

При старте устройство-ведущий:
1. берёт активные карточки, отбрасывает `hard`, если «Жёсткие» выключены, и ограничивает каждый пул 120 карточками (случайная выборка), всего до 480, чтобы `ids` уложилось в 12000 знаков (480 × 19 знаков при самом длинном `id` ≈ 9100);
2. собирает **четыре пула**: `truth` (все разрешённые уровни), `dare.easy`, `dare.medium`, `dare.hard`;
3. записывает в `ids` JSON `{ seed, pools: { truth: [id…], 'dare.easy': […], … } }`, где `seed` — случайная строка.

Порядок выдачи считают все устройства одинаково: `order(pool, round) = shuffle(pool, seed + ':' + pool + ':' + round)` (Fisher–Yates с детерминированным генератором). В `st` лежат только курсоры: `cur[pool] = { round, i }`. Следующая карточка пула — `order[i]`; когда `i` доходит до конца, `round` растёт, курсор обнуляется (перемешиваем заново, всем игрокам показывается реплика «круг закончен»).

Следствия: нет гонки за «случайную» карточку, повторов нет до исчерпания пула, колода маленькая (только `id`), любое устройство может продолжить игру. Текст карточки каждое устройство берёт из своего загруженного набора по `id`; если карточки нет, делает точечный запрос `tod/<id>`.

## 8. Правила игры и состояние

`st = { v:1, gid, phase, turn, pl, type, diff, card, streak, seq, ev, cur, opts, stat, log }`

- `pl` — снимок игроков на момент старта `[{id,name,gender}]`; `turn` — индекс игрока в `pl`.
- `opts = { hard: bool, tone: 0|1|2 }` (0 — подколки выключены, 1 — мягкий, 2 — острый).
- `phase`: `choose` → (`level`, если выбрано «Действие») → `card` → снова `choose`; `ended` — после «Завершить».
- `streak` — число пропусков подряд у текущего игрока в этот его ход; `seq` — счётчик действий.
- `card = { pool, id }` — текущая карточка; `ev = { k, seq }` — событие последнего действия для подколки (раздел 9.1).
- `stat` — компактные счётчики по каждому игроку: выполнено и пропущено по четырём группам (правда, лёгкие, средние, жёсткие), выборы «правда/действие» и выборы уровней, максимум пропусков подряд, число искуплений. `log` — кольцо из последних 30 пропусков `[индекс игрока, пул, id]` для итогов. При 10 игроках `st` занимает меньше 4000 знаков (лимит 20000).

Действия (`applyAction`) и их эффекты:

| Действие | Условие | Эффект |
|---|---|---|
| `choose(type)` | `phase = choose` | `truth` → сразу выдаётся карточка (`phase = card`); `dare` → `phase = level` |
| `level(diff)` | `phase = level`, уровень разрешён | выдаётся карточка `dare.<diff>` |
| `done` | `phase = card` | статистика игрока +1 (тип и уровень); если `streak > 0`, игроку засчитывается «искупление»; `turn = (turn+1) % n`, `streak = 0`, `phase = choose` |
| `skip` | `phase = card` | `streak += 1`, пропуск пишется в статистику (тип, уровень, карточка); `phase = choose`, **`turn` не меняется** |
| `end` | любая фаза | `status = ended`, `phase = ended` |

Конкурентность: каждое действие несёт `seq`, на который рассчитывал отправитель; если в канале уже другой `seq`, действие молча отбрасывается (двойной тап, два телефона нажали одновременно). Запись идёт версией по правилам классической игры (побеждает более новая `ver`), проигравший перечитывает состояние.

Присутствие и лимит: используются готовые `liveAlive` и `deviceCap(profile, snap)`. Подключение сверх лимита отклоняется тем же сообщением, что и в классической игре. 

Граничные случаи:
- Карточка, которую выполнили или пропустили, уже вышла из пула: до конца круга она не повторится.
- Если в пуле нет активных карточек (например, нет жёстких), кнопка уровня недоступна с подписью «пока пусто». Старт невозможен, если нет «Правды» или нет ни одного уровня «Действия».
- Новая партия перезаписывает узел `_t` (новый `gid`). Старые узлы не удаляются: то же ограничение, что у классических комнат.
- Лобби блокирует старт, пока классическая комната сессии активна и жива по присутствию («В сессии идёт классическая игра — завершите её»). Обратной проверки в классическом режиме нет, его код не меняется: если два режима всё же запущены на разных устройствах, они работают независимо.

Подключение других устройств. Устройства, не начинавшие игру, узнают о ней так же, как о классической: на экранах `menu`, `mode_select` и в лобби `#/tod` раз в `LIVE_INVITE_MS` опрашиваются `status` и `p` узла `_t`, и показывается баннер «Идёт игра «Правда или действие» — присоединиться» (оформление как у `liveInviteBanner`). Нажатие подключает устройство с проверкой `deviceCap`. Если в игре включены «Жёсткие» или тон «Острый», перед входом показывается предупреждение 18+ с кнопкой «Понятно». На экране итогов баннер предлагает присоединиться к новой партии, если кто-то нажал «Сыграть ещё».

Перезагрузка. После перезагрузки на любом адресе `#/tod…` приложение сначала восстанавливает профиль сессии и идентификатор комнаты (как для классической игры), затем читает `_t`: `active` возвращает в игру, `ended` показывает итоги, пустой узел или отсутствие профиля ведут в главное меню. Локального сохранения игры нет.

## 9. Подколки, тон, титулы, итоги

### 9.1 Подколки

События: `turn_start`, `chose_truth`, `chose_dare`, `level_easy|medium|hard`, `done`, `done_hard`, `skip` (степень 1, 2, 3+ подряд; отдельные для `hard`), `redeem` (выполнил после пропусков), `same_type_streak` (3 одинаковых выбора подряд), `easy_only`, `deck_cycle`, `game_end`. Событие `easy_only` означает три выбора «Легко» подряд.

На каждое действие выбирается одно событие по приоритету: `game_end` > `redeem` > `skip` > `deck_cycle` > `same_type_streak` > `easy_only` > `done_hard` > `done` > `level_*` > `chose_*` > `turn_start`. Код события лежит в `st.ev` вместе с `seq`, а текст каждое устройство выбирает само по формуле ниже, поэтому реплики по сети не передаются.

Реплика — объект `{ id, ev, tone: 1|2, text, tags? }`. В тексте: `{name}` — имя, `{a|b}` — форма по полу игрока (`guy` → `a`, `girl` → `b`). Выбор реплики детерминирован: `index = hash(gid, seq, event) % N`, поэтому на всех устройствах одна и та же. Показывается под карточкой с мягким появлением (`transform` + `opacity`, `prefers-reduced-motion` учитывается).

Тон выбирается пулом: «Мягкий» — реплики `tone: 1`; «Острый» — реплики `tone: 2`, а при их нехватке для события — `tone: 1`.

### 9.2 Границы содержимого (проверяются тестом и ревью)

- Политическая сатира — только на государство-агрессора, его режим, армию как институт и пропаганду. Строки помечены тегом `ua` и могут быть выключены одним фильтром.
- Нет шуток над людьми по национальности или языку, этнических оскорблений, призывов к насилию и прославления убийств.
- Нет шуток над погибшими, пострадавшими, мобилизованными, жителями оккупированных территорий и реальными трагедиями. Чёрный юмор «игровой» («умер со стыда»).
- Вульгарность только лёгкая («хрень», «задница», «чёрт»), без оскорблений групп людей.
- Подколки — над поведением в игре (струсил, выбрал полегче, пропустил), а не над внешностью, телом, полом и личной жизнью.
- Для тона «Острый» и «Жёстких» обязательно предупреждение 18+ (раздел 10).

Для `tests/unit/content.test.js` добавляется проверка реплик: нет пустых и дублей, обе формы по полу, известные подстановки, длина, теги, стоп-список оскорбительных слов, достаточное число реплик на каждое событие и тон.

### 9.3 Титулы и «Зал позора»

Статистика по игрокам: выполнено (по типам и уровням), пропуски (по типам и уровням), максимум пропусков подряд, искупления.

| Титул | Условие |
|---|---|
| Главный трус вечера | больше всех пропусков (минимум 2) |
| Серийный дезертир | 3+ пропуска подряд за ход |
| Пасует перед жёстким | пропустил карточку уровня `hard` |
| Вечное «давай потом» | пропусков больше, чем выполненного (минимум 3 карточки) |
| Любитель лёгкой жизни | 80%+ выбранных уровней — `easy` (минимум 4 действия) |
| Боится действий | не выбрал ни одного «Действия» (минимум 4 хода) |
| Вечный осторожный | «Жёсткие» включены, а игрок ни разу не выбрал уровень «Жёстко» (минимум 4 действия) |
| Герой вечера | больше всех выполненных `hard` |
| Бесстрашный | без пропусков (минимум 5 выполненных карточек) |
| Искупил вину | выполнил после 2+ пропусков |
| Мастер действий | больше всех выполненных «Действий» |
| Самый честный | больше всех выполненных «Правд» |

Титул выдаётся детерминированно. «Главный трус», «Герой вечера», «Мастер действий» и «Самый честный» достаются одному игроку, при равенстве — тому, кто раньше в списке `pl`. У игрока не больше двух титулов (по порядку таблицы). Если пропусков не было, в «Зале позора» пишем «Сегодня без позора» и хвалим всех. На экране итогов позорные титулы идут первыми и крупнее добрых.

## 10. Экраны, дизайн, доступность

Дизайн-система «Heat»: только существующие классы (`btn-*`, `opt-card`, `tile`, `seg`, `tag`, `row`, `chip`). Новые классы фиксируются в `claude/design-system.md` в том же заходе. Шрифт Onest, текст не меньше 13 px, нажимаемые элементы не меньше 44 px, на экране одно главное действие. Анимируются только `transform` и `opacity`.

- **Вход:** новая карточка режима на экране «Выберите режим» (без изменения двух существующих).
- **Лобби `#/tod`:** список игроков сессии с иконками, число подключённых устройств, «Поделиться сессией». Опции: переключатель «Жёсткие 18+» (выкл.), сегмент тона «Выкл / Мягкий / Острый». Кнопка «Начать игру». При включении «Жёстких» или «Острого» показывается подтверждение: «Игра для взрослых: откровенные карточки, вульгарность и чёрный юмор. Пропуск засчитывается в итогах как позор. Играйте только с теми, кому комфортно». Старт доступен после подтверждения.
- **Игра `#/tod/play`:** крупно «Ход игрока: Имя» и счётчики «🐔 N» у игроков; две большие кнопки-карточки «Правда» и «Действие»; у «Действия» подменю «Легко / Средне / Жёстко» (зелёная, янтарная, красная; цвет не единственный признак: есть подпись и значок); переворот карточки; реплика под карточкой; главная кнопка «Выполнено — передать ход» (у «Правды» — «Ответил(а) — передать ход») и второстепенная «Пропустить». Кнопка «Завершить» в меню игры.
- **Итоги `#/tod/results`:** «Зал позора» (титулы и рейтинг пропусков), добрые титулы, итоговая таблица, кнопки «Сыграть ещё» и «В меню».
- **«Все вопросы»:** вверху сегменты «Классика / Правда / Действие». «Правда» и «Действие» — списки, сгруппированные по уровням («Простые / Средние / Жёсткие») с цветом уровня. Скрытые (`isActive = false`) видит только владелец, помечены значком.
- **Админка `#/tod/manage`:** новый пункт в зоне владельца («видите только вы»). Фильтры по типу и уровню, добавить (тип, уровень, текст), изменить, тумблер «Показать / Скрыть». Кнопки физического удаления нет. Проверка длины и повторов текста, ошибка запроса показывается понятным текстом.

Юридические тексты: в `src/content/legal.js` (политика конфиденциальности, возраст 18+) добавляется описание режима: что лежит в канале (имена, выбор, пропуски), что узел не шифруется, откровенный и грубый контент, 18+. В `about.js` — короткое описание режима. Описание для магазинов фиксирует возрастную метку: режим содержит вульгарность, откровенные темы и политическую сатиру (анкеты возраста Apple и Google заполняются честно; Google Play запрещает неуважение к реальным трагедиям, Apple допускает политическую сатиру при отсутствии нападок на группы людей).

## 11. Безопасность

- Запись в `tod` — только владелец по `uid`, чтение открыто; карточки проверяются правилами и клиентом (`cleanCard`), текст выводится как текст, не разметка.
- Канал `_t` пишет любой, кто знает ключ сессии, как у классической комнаты; размеры `st` и `ids` проверяются клиентом (в правилах лимит есть только у `ids`, см. 6.3), индексы и курсоры ограничиваются длиной пулов, данные канала проходят `engine.sanitize` перед применением (как мы делаем для классической комнаты).
- Режим 18+ включается только осознанно (подтверждение). Политический контент имеет тег и проверяется тестом.
- Никаких секретов в репозитории; идентификатор владельца в правилах-копиях заменён.

## 12. Тесты

- Юнит: `deck` (нет повторов до исчерпания, одинаковый порядок у двух вычислений, `round` растёт), `engine` (все действия, пропуски подряд, искупление, `seq`-конфликты, неверные данные канала, титулы, детерминизм реплик), `model` (`cleanCard`).
- Контент: `tod-cards.js` (поля, уровни, длины, нет дублей), `tod-banter.js` (раздел 9.2).
- Интерфейс (jsdom, несколько «телефонов» на общей базе в памяти по правилам из `fixtures`): лобби и лимит, старт, ход по кругу, «Правда» и «Действие» с уровнями, пропуск и сохранение хода у пропустившего, подколка видна на всех устройствах, итоги, перезагрузка в игре, выход одного устройства, баннер приглашения и подключение второго устройства, предупреждение 18+ при входе, блокировка старта при активной классической комнате, вкладки «Все вопросы», админка (создание, правка, скрытие), проверка записи карточки по `tod-rules.json` (чужой пользователь не может писать, лишние поля отклоняются).
- Реальный браузер: Playwright на 320/360/390/430 px и на ПК (вёрстка на длинных русских строках, переворот карточки, `prefers-reduced-motion`).
- Всё это входит в `npm run verify`; вес первой загрузки остаётся в пределах 500 КБ (gzip).

## 13. Этапы выкладки

Каждый этап — отдельный коммит с зелёным `npm run verify` и проверкой CI.

1. **Данные и админка:** `tod-cards.js`, `model.js`, правила и копия `tod-rules.json`, загрузка с кэшем, админка (CRUD, скрыть/показать, разовая загрузка набора), вкладки «Все вопросы», расширение тестовой среды. Публикация правил `tod` — только после отдельного «да».
2. **Игра на одном устройстве:** `deck.js`, `engine.js`, `tod-banter.js`, лобби, игровой экран, пропуски и подколки, итоги.
3. **Синхронизация:** `channel.js`, присутствие и лимит, перезагрузка в игре, обновление `update.js`, юридические тексты, README и дизайн-система.

Содержимое (карточки, реплики): черновики «мягких» могут делаться через `ask_gemini` и обязательно проходят мою проверку; «острые», политические и 18+ пишутся мной. Владелец просматривает файлы содержимого перед публикацией.

## 14. Риски и открытые вопросы

- **Магазины.** Режим 18+ с политической сатирой повышает риск замечаний при проверке; снижаем теги, границы раздела 9.2, честной возрастной анкетой. Гарантировать одобрение нельзя.
- **Правила базы.** Без публикации правил `tod` админка не сможет писать; чтение карточек пока работает из запасного набора.
- **Размер канала.** До 480 карточек на игру (по 120 на пул), `ids` до 12000 знаков; при росте базы потребуется вынести колоду в отдельный узел (как `_d`).
- **Старые узлы `_t`.** Автоматической очистки нет, как у остальных комнат `live`.
- **Редактирование текста во время игры.** Устройства могут на короткое время показать разные редакции одной карточки; считаем допустимым.
- **Политика контента проекта.** В инструкциях проекта сказано «никаких политически острых тем в самой игре»; для этого режима владелец решил иначе. Остальные режимы остаются без политики.
